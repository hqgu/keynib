## 2. 厂商浏览器直连（CORS）——服务器侧预检
方法：`npm run probe:cors`，模拟浏览器从 `https://localhost:3000` 发出 OPTIONS 预检，以及带错误 Key 的实际请求，检查 `Access-Control-Allow-Origin`（ACAO）。网络环境：本机（经本地代理）。

| 厂商 / 端点 | 预检 | 错误 Key 请求 | ACAO | 结论 |
|---|---|---|---|---|
| Anthropic `api.anthropic.com/v1` | 200 | 401 | `*`，放行 `anthropic-dangerous-direct-browser-access` | ✅ 直连 |
| OpenAI `api.openai.com/v1` | 200 | 401 | `*` | ✅ 直连 |
| Gemini OpenAI 兼容 | 200 | 400 | 回显来源 | ✅ 直连 |
| Gemini 原生（`x-goog-api-key`） | 200 | — | 回显来源 | ✅ 直连 |
| xAI `api.x.ai/v1` | 200 | 400 | `*` | ✅ 直连 |
| DeepSeek `api.deepseek.com` | 200 | 401 | 回显来源 | ✅ 直连 |
| GLM 国内 `open.bigmodel.cn` | 200 | 401 | 回显来源 | ✅ 直连 |
| GLM 国际 `api.z.ai` | 200 | 401 | 回显来源 | ✅ 直连 |
| MiniMax 国内 `api.minimaxi.com` | 200 | 401 | 回显来源，放行 Authorization | ✅ 直连 |
| MiniMax 国际 `api.minimax.io` | 200 | 401 | `*` | ✅ 直连 |

**结论**：7 家（10 个端点）服务器层面都允许浏览器直连，包括错误响应也带 CORS 头。这意味着前端能把 401/400 的具体原因展示给用户。
- 纯 BYOK、无后端的架构成立；中转降级为 Could 项，只用于网络不可达的场景。
- ✅ **Office 内复测（2026-11-22，Mac PowerPoint 16.112，WKWebView，来源 `https://localhost:3000`）**：7 家全部可达，均拿到 401/400 状态码，耗时 1.6–3.5 s（经本地网络）。

### 对设计的影响
1. **"撤销本轮"路线成立**：导出 / 插回无损。插回后 ID 变化，快照层必须在还原后更新会话里所有对该页的引用（按"位置 + 快照映射"重定位）。
2. **原生 ⌘Z 可用**：用户习惯的撤销也能生效，但一轮 Agent 可能包含几十次写入，⌘Z 要按很多次。所以保留"撤销本轮"作为主入口，帮助中说明 ⌘Z 也可用。
3. **界面语言**：该机 Office 显示语言为 en-US，但用户以中文交流。界面语言默认跟随 Office，设置中可手动切换，首次引导时询问。
4. **纯前端 BYOK 在 Office 内确认可行**（三宿主均直连 7 家），中转保持 Could。
5. **Key 与设置不能跨宿主共享（Mac）**，这对用户体验影响最大。对策（已写入规划 v0.2 §8.1）：
   - 首次引导提供“从其他 Office 程序导入”：在已配置的程序里点“复制配置码”，到新程序粘贴即可。配置码含 Key 时必须口令加密（PBKDF2 + AES-GCM），不含 Key 时为明文。
   - 三个程序各自保存会话历史（会话本来就按文档绑定，影响不大）。
   - 规范档案、快捷指令同样随配置码迁移。

## 6. Word 修订探针（2026-11-22，Mac Word 16.112，WordApi 1.9，空白未保存文档）
方法：`node scripts/bridge.mjs --host Word wordProbe`（`apps/taskpane/src/probes/wordProbe.ts`）。不开修订写入标题 + 中文段落 → 开 trackAll → 按"。"切句并替换第 2 句 → 检查 → 改标题样式、插表格 → rejectAll → 恢复原修订模式。

| 问题 | 结果 |
|---|---|
| 修订后 `paragraph.text` 是否混入已删除文字 | ✅ 否，只含当前文本；`getReviewedText('Original')` 可取原文 |
| `search()` 是否命中已删除文字 | ✅ 否（0 次）；新文字命中 1 次 |
| 超长检索 | ❌ > 255 字报 `SearchStringInvalidOrTooLong` |
| 中文按句切分 `getTextRanges(['。'])` | ✅ 3 句，末句带 `\r` |
| TrackedChange 字段 | type：Added / Formatted；author = Office 用户名；date 精确到分钟 → 不能靠时间识别"本轮"，需前后列表对比 |
| 替换句子产生的条目 | ⚠️ 仅 1 条 Added，无单独 Deleted 条目；但 rejectAll 后被删文字也恢复 |
| 样式修改 / 插入表格 | 均记为修订（Formatted / Added） |
| rejectAll 后 | ✅ 段落与原文逐字一致；表格消失；标题样式还原为 Heading1；无残留修订 |
| 修订模式 | ✅ finally 中恢复为原值（Off） |

### 对 M2 设计的影响
1. 读取直接用 `paragraph.text`。
2. 修改粒度：按句切分，句内用"公共前缀 / 后缀"缩到最小差异片段再 `search` 替换；检索词 > 255 字、命中不唯一或含特殊字符时退回整句替换。
3. "本轮修订"= 本轮前后 `getTrackedChanges()` 列表之差（按 type + text + date 键），不能仅按时间；拒绝本轮不影响用户已有修订。
4. Word 的"撤销本轮" = 拒绝本轮修订；修订存于文件中，面板刷新不丢（PPT 的内存限制不适用于 Word）。
5. 待验证：对"替换"产生的单条 Added 执行单独 reject，是否同样恢复被删文字。
